# CLAUDE.md

## What this is

**Vellum** — a multilingual Hugo theme that sets every page as an engineering drawing sheet: a drawn frame, and a ruled **title block** carrying the post's metadata instead of a grey caption line. The zone rail down the frame's left edge is a real section index — one lettered zone per top-level heading, each a link — and it renders only on pages that have sections to index, never as lettering over an empty field.

It is developed standalone. It lives at `gitlab.stkn.org:felix/vellum`, is committed to directly on `main`, and publishes `exampleSite/` to GitLab Pages from there.

A second copy lives at `github.com/cebor/vellum`, and it is **pushed by hand — automatic mirroring is deliberately switched off and is to stay off.** Nothing propagates on its own, so `git push github main --follow-tags` is a required step of every release, not a convenience. That copy is not incidental: **`github.com/cebor/vellum` is the module path listed on themes.gohugo.io**, so it is the address users install from and file issues against, and every user-facing URL in `README.md`, `theme.toml` and `exampleSite/hugo.toml` points there rather than at GitLab. Two things follow. A release only counts once its tag has reached GitHub — the registry reads the *latest tag*, not `main`, so verify with `git ls-remote --tags https://github.com/cebor/vellum.git` after pushing. `.release/release.sh` is the whole procedure and does exactly that; never cut a release by hand. And `images/` holds nine tracked fixtures, not stray build output, in two formats along one line: the registry accepts only `.png`/`.jpg`, everything else is read by a browser and is free. `screenshot.png` (1500×1000) and `tn.png` (900×600) are the registry fixtures: they must be in the tagged release or the theme gallery shows a placeholder, and both are 3:2 PNG for that reason. `hero-light.webp`/`hero-dark.webp` (1500×1000) are what the README's `<picture>` element loads over the raw URLs, which is why a hand-pushed GitHub copy that lags behind shows a broken image on the first thing a user reads — and there are now five more that fail the same way: `gallery-terminal-{light,dark}.webp` and `gallery-icons-{light,dark}.webp` (1500×1000) plus `gallery-print.webp` (900×1240, paper proportions rather than 3:2, because a print stylesheet stretched across 1500px is not what a printer does with it). The seven WebP are **lossless** — identical pixels at about a third of the bytes, which matters because every tracked byte is downloaded by every site that runs `hugo mod get` on this theme. All nine are cut by `node .parity/shots.mjs --fixtures` against a running dev server — viewport clips, never `fullPage`, because 3:2 is a hard requirement and a full-page frame is whatever height the page happens to be. The registry pair is additionally a **split**: one frame carrying both schemes, light left of the centre line and dark right of it, because the gallery shows exactly one image per theme and a light-only preview never said the dark scheme existed. The cut is vertical for a reason — both halves are the same page at the same viewport, so the header rule, the frame's top edge and every title-block row rule run unbroken through the seam and only the paper and the ink change; a diagonal would slice each of those at an angle. Nothing the README loads is split, and that rule now covers the gallery too: a `<picture>` already hands each reader the right full-width variant, so splitting one would trade a working mechanism for half the resolution per scheme — and two of the gallery frames could not be split at any price, since a seam through the icon grid bisects a cell and truncates its name, and the terminal measures its own window and animates, so its two loads are two different states. The split is also why the registry pair now shoots a post rather than sitting on the home page as it used to — a split needs content either side of the centre line, and the home page has none to give: profile, buttons and post titles all fall in the left half, so the dark half came out an all but empty field that reads as a broken image at thumbnail size. The compositing is done by the browser that is already open — the two frames go in as data URIs and the dark one is clipped to the right half — rather than by an image library, because the halves have to meet on a seam running through rules that browser laid out. `sharp` is now a **devDependency** of the harness and does the encoding only, where the pixels are already fixed; `playwright-core` remains the only thing an ordinary review shot needs. The reason once given here for keeping it the *only* dependency — that anything vendored would ride into every consuming site's module cache — does not hold: `node_modules/` is in `.gitignore`, so a module download takes `package.json` and `package-lock.json` and nothing else. Keep the runtime dependency single because the harness should stay trivially installable, not because of module weight. `release.sh` checks all nine dimensions — `check_img` dispatches on the extension, reading the PNG IHDR with `od` and delegating WebP to sharp, because lossless WebP is VP8L with the dimensions bit-packed or VP8X with them as 24-bit LE, and an `od` recipe covering both would be quietly wrong when it was not — but it cannot tell a themed 404 from a home page, so the fixture mode asserts each route's status and writes nothing unless all nine succeed. Two fixtures are staged rather than merely loaded: every fixture context runs `reducedMotion: 'reduce'`, without which the smooth-scroll in `10-base.css` is still in flight when an anchored frame is shot and the terminal's character-at-a-time output makes two loads two different states; and the terminal frame clicks its own `skills` button first, because a window opened on `help` at 24 rows is two-thirds empty field. `hugo.toml` at the root exists solely to declare `[module.hugoVersion]` — the only form Hugo enforces and the only one the registry reads.

`README.md` is the user-facing documentation — params, front matter, shortcodes, icon set — and `exampleSite/` is the only site in this repository and the only thing that exercises the theme, so a param it never sets is a param nothing tests. A param that isn't in the README does nothing; add it there when you add it to a template.

The demo carries a `docs/` section (`exampleSite/content/{en,de}/docs/`), and the line between it and the README is by **kind, not by topic**: the README is the reference — exhaustive tables, in the module, works offline, and the one page a themes.gohugo.io visitor lands on — while the docs pages show the theme working and **never repeat a table the README owns**. Cross-link instead of duplicating; two copies of a param list drift and the README's is the one users will have. Each page also has to earn its place by exercising something: `docs/icons.md` renders every branch of `icon.html` including the unknown-name fallback, which nothing else in the demo did, and `exampleSite/assets/css/99-local.css` exists so the site-CSS extension point the README documents is finally walked rather than merely described. That is not hypothetical — walking it is what turned up `head-assets.html`'s `resources.Match` ordering, below.

## Structure

Requires Hugo extended ≥ 0.158 — `site.Language.Locale` and `.Language.Label` are used unguarded in seven templates and neither exists before that, so a lower version fails at render time, not with the version guard's message. Uses Hugo's flat layout structure: templates directly in `layouts/` (`baseof.html`, `home.html`, `list.html`, `single.html`, `term.html`, `taxonomy.html`, `archives.html`, `search.html`), partials in `layouts/_partials/`, render hooks in `layouts/_markup/`, shortcodes in `layouts/_shortcodes/`. There is no `layouts/_default/` and no `layouts/partials/` — putting files there silently does nothing.

Four render hooks carry behaviour the site depends on, not just styling:

- `_markup/render-image.html` resizes bundled images to a 480/800/1600 WebP ladder (the ladder is derived from `--content-width`, so those numbers move with it) with a `sizes` attribute and intrinsic `width`/`height`, so they neither shift the layout nor ship at source resolution. An image referenced from outside a page bundle is passed through untouched and gets none of that.
- `_markup/render-table.html` supplies the `.table-wrap` scroll container that `50-single.css` styles. Goldmark's default `<table>` has no wrapper, and a wide one pushes the whole page sideways.
- `_markup/render-blockquote.html` turns `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` into labelled alerts, which is why posts never need raw HTML (Goldmark's `unsafe` is off).
- `_markup/render-codeblock.html` exists so the theme needs no `markup.highlight` config from its consumer: it merges `noClasses: false` over the fence's own options, so Chroma emits the class names `90-syntax.css` maps instead of baking a palette into the markup (Hugo's default is monokai — a dark box on a light sheet). `.Inner` arrives without the fence's closing newline and the hook puts it back; drop that and every code block loses its last line break and the word counts shift. It does not reach Hugo's built-in `{{< highlight >}}` shortcode, which bypasses render hooks.

`_partials/config-guards.html` announces the two settings the theme needs but cannot set for itself — the JSON home output that *is* the search index and the `ROOT404` output format. It is called once from `baseof.html` via `partialCached` on a constant key, so **nothing in it may read the current page**; every check is a property of the site. Both use `warnidf`, not `errorf`: they are the consuming site's settings, and an upgrade must not break a build that has been running half-configured. Chroma's class mode was a third guard until the render hook above settled it — a theme's own `[markup]` is *not* merged into its consumer's config, but a render hook does not need it to be, so what looked like the site's setting was the theme's all along. Before adding a guard, check that the theme really cannot do it itself.

`layouts/home.root404.html` and `layouts/baseof.root404.html` render the site's root `/404.html`. The identifier `root404` is the consuming site's `[outputFormats.ROOT404]` name lowercased — rename the format there and both files stop matching silently. That baseof deliberately omits canonical, hreflang, OpenGraph and analytics: Hugo reports the *home page's* permalink while rendering it, so the shared `head.html` cannot recognise it.

## CSS

CSS lives in `assets/css/` as numerically prefixed files (`00-tokens.css` … `95-print.css`). They are globbed, concatenated, minified and fingerprinted into one stylesheet, so **the numeric prefix is the cascade order** — a new file needs a prefix that places it correctly (`95-print.css` sits after `90-syntax.css` precisely so its `@media print` rules can override the syntax colors).

The glob is **sorted by name explicitly**, and that is load-bearing rather than tidiness: `resources.Match` walks the union of the consuming site's `assets/` and the theme's and returns the site's run first, so a site's `css/99-local.css` was concatenated *before* `00-tokens.css` and lost every tie at equal specificity — the exact opposite of what the README's "Your own CSS" promises, and silent, because a local rule that happened to carry more specificity still won. The theme's own files are already in prefix order, so the sort moves nothing but the site's. Verify a change here by adding a one-class rule to `exampleSite/assets/css/99-local.css` and checking it wins; specificity will mask the bug otherwise.

One file leaves the glob conditionally: `head-assets.html` drops `35-terminal.css` unless the site sets `profile.view = "terminal"`. It is the only such exception and the bar for a second one is the same one it clears — the terminal is the theme's only feature that is **off by default**, so it is the only sheet a site can be shipping for markup no page of it will ever contain (every other numbered file is live somewhere on every site), and every selector in it begins with `.term`, print rules included, so removing the file removes the feature and nothing else. It is worth about 1.1 KB gzipped, which is small; the argument is that a theme should not ship a disabled feature's CSS, not page weight. Three things make it work and each fails silently if dropped. The sheet is filtered out of the concat rather than served as a second `<link>`, because a second sheet would load *after* this one and put the terminal's screen rules after their own print overrides, which win on source order at equal specificity. The two variants must use **different `resources.Concat` target names** — Hugo caches a concatenated resource under its target path, so a second call naming `css/main.css` in one build is handed the first one's bytes whatever its inputs were, and `exampleSite` sets the view per language, which is exactly that case. And `partialCached "head-assets.html"` is keyed on the view value rather than a constant, because the partial cache is shared across a build's languages — the same reason `baseof.html` hands `footer.html` its `.Lang`. Verify a change here by checking that `en/index.html` and `de/index.html` name *different* stylesheets; a wrong key or a shared target name shows up as both naming the same one.

`00-tokens.css` is the single source of truth for color, type, space and motion, and **no other file may carry a bare hex, a type step, a spacing step or a transition duration**. Four exceptions are allowed and each has to say so at the declaration: `95-print.css` sets paper ink (white, black, two greys) rather than the screen palette, because paper is not a surface the palette was contrast-checked against; `10-base.css`'s `prefers-reduced-motion` block uses the standard `0.01ms`; a one-off component geometry — the title-block label column, the card's cover column, the archive date column — is a literal at its point of use, because it belongs to that component and to nothing else; and a media-query breakpoint is a literal because a media query cannot resolve `var()` (only two exist, `40rem` = `--sheet-narrow` and `60rem` = `--frame-collapse`, both also declared as tokens so `tokens.html` can read them). Anything that is a *scale* value comes from a token. Colors resolve through CSS `light-dark()`, so each one is written once: `color-scheme: light dark` on a bare `:root` is what `data-theme="auto"` matches, and the explicit `[data-theme="light"]` / `[data-theme="dark"]` rules override *only* `color-scheme`, never the palette. The page therefore still themes correctly with JavaScript disabled, and there is no *per-scheme* block to keep in sync. There is one restatement, and it is not a scheme: the `@supports not (color: light-dark(…))` block at the foot of the file repeats the **light** palette for browsers under the baseline, which would otherwise get no value at all for every colour and render as broken rather than plain. It is kept in step by hand — a colour changed above is changed in both places or in neither, and the two are currently identical across all 30 tokens. This raises the effective browser baseline to Chrome 123+ / Safari 17.5+ / Firefox 120+. Two consequences worth remembering: a rule that needs to *override* `color-scheme` must repeat the `[data-theme]` selectors to win on specificity (see `95-print.css`), and a display swap like the theme-toggle icon still needs a real `prefers-color-scheme` media query because `light-dark()` only produces colors.

Sizes come from the same file: `--step--2` … `--step-5` for type and `--space-4xs` … `--space-4xl` for spacing. `--step-0` is body, 20px, which sets the 800px column at **92 characters** — counted from a rendered line, not estimated, where a conventional column of the same body size measures 83. That is deliberately past the classic 65–75 advice: command blocks and terminal output are the substance here and should not wrap, and `--line-height: 1.75` is what keeps a line that long trackable. Recount with a real rendered line before changing either number; a characters-per-pixel estimate is reliably wrong. Dim text by dropping to `--meta-soft` and a smaller step, never by lowering opacity — every text token is contrast-checked at ≥ 4.5:1 against its surface in both schemes, and an `opacity: 0.6` silently undoes that. Touch-target minimums live behind `@media (pointer: coarse)` so the pointer layouts keep their density.

Six token values are also parsed out of `00-tokens.css` at build time by `_partials/tokens.html` — `--content-width`, `--sheet-gutter`, `--sheet-gutter-narrow`, `--sheet-narrow`, `--bg` and `--accent` — because an image `sizes` attribute, a `theme-color` meta and the `mask-icon` tint are evaluated without element context and cannot use `var()`. `--content-width` *is* the reading column, so the frame arithmetic in `20-layout.css` has to keep resolving to it; when that drifted, every image silently advertised the wrong `sizes`. That is what keeps the responsive-image breakpoint from silently disagreeing with the layout; renaming any of the five fails the build loudly instead. Never hardcode those numbers in a template.

Any asset referenced only from CSS must have its `RelPermalink` evaluated somewhere in a template, or Hugo never publishes it and it 404s in production while working locally.

## Fonts

The theme self-hosts two variable faces in `assets/fonts/`: **Archivo** (its width axis supplies both the reading face and the narrow tracked lettering of the title blocks) and **JetBrains Mono** for code. Roughly 121 KB on first load, cached thereafter.

## Commands

```bash
hugo server -D --source exampleSite --themesDir ../..   # the theme's own demo site
```

`exampleSite/` is the only site in this repo, so it is what every change is tested against; content that a template needs in order to be exercised has to be added there.

Hugo extended is required. There are no tests, linters, or package manifests for the theme itself — `.gitlab-ci.yml` builds `exampleSite/` on every branch and publishes it to GitLab Pages from `main`, so that build is the only thing standing between a broken template and the demo. It symlinks the repo root to `exampleSite/themes/vellum` instead of passing `--themesDir`, and takes its `--baseURL` from `CI_PAGES_URL` because the demo is served from a subpath.

## Design harness

- `PRODUCT.md` records what the theme is for and who it is built for first, and marks which of its properties are binding commitments (URL-surface stability, 4.5:1 text contrast) against which are merely true today and may be traded deliberately (no-JavaScript operation, no third-party requests). A change to the latter is not a defect.
- `DESIGN.md` records the built visual world (line-weight system, palette, motion, print) and the load-bearing rules. It describes what the stylesheet *is*; where the two disagree, the stylesheet is right and `DESIGN.md` is stale.
- `.impeccable/` is the impeccable skill's state: `critique/` holds the review rounds, `live/` the browser-iteration state, `config.local.json` the per-machine consent and overrides, `hook.cache.json` the detector's cache, `questions/` one hash-named log per prompt the hook asked. `config.json` holds the shared detector ignore rules and currently waives nothing; the one entry it briefly carried described a `border-left: 3px solid var(--border-strong)` that no commit in this repo has ever contained. Any entry must carry the reason it is not a defect — a rule waived without one is indistinguishable from a rule someone silenced — and must be one the detector actually emits: for a rule with no extractable value, such as `side-tab`, the only form that suppresses anything is `"*"` scoped to a file glob, which turns that rule off for the whole file. Prefer an inline `/* impeccable-disable-line <rule> */` at the declaration, which travels with the line it excuses. Only what this project authored is tracked — the `critique/` rounds, `config.json` and `live/config.json`; the machine-local state and the runtime logs are ignored. The skill itself lives in `.claude/skills/impeccable/`, its four subagent definitions in `.claude/agents/impeccable-*.md`, and its hooks are wired in `.claude/settings.local.json`; **all three are deliberately untracked**: it is third-party tooling with its own upstream, and a Hugo module download takes the whole repo, so 4.8 MB of it would ride into every consuming site's module cache. The agents were briefly tracked, on the grounds that four files and 36 KB is not the 4.8 MB — but they are vendored just the same, `npx impeccable update` rewrites them, and a tracked copy turns every upstream bump into a diff in this repository's history. Ignoring them settles the untracked directory that made the release preflight fail on a dirty tree just as well as tracking them did. Each is named individually in `.gitignore` rather than the whole `.claude/skills/` and `.claude/agents/` directories, so a skill or agent this project does author shows up in `git status` instead of being ignored in silence. A checkout that needs it runs `npx impeccable install`, and `npx impeccable update` pulls a newer version — that is what makes leaving it out cost nothing, so the two commands are the reason this rule is safe, not a footnote to it.
- `CONTRIBUTING.md` fixes the commit format (`type(scope)!: summary`, Conventional Commits) because commits are the changelog source, and records the release procedure. `.release/changelog.sh` renders one `CHANGELOG.md` section from a commit range — only `feat`, `fix`, `perf`, `revert` and anything breaking; `.release/release.sh` runs the preflight, derives the version (below 1.0 a breaking change bumps the *minor*), writes the changelog, tags with the section as the tag message, pushes both remotes and verifies the tag arrived. It refuses to release on an unparseable commit or a failed parity check, and depends on `.parity/check.sh`, which is tracked — so every checkout can cut a release, and its guard now catches a broken checkout rather than the wrong machine.
- `.parity/` compares built URL surfaces. `shots.mjs` takes batched desktop/mobile, light/dark screenshots against a running server, and asserts every route's HTTP status before shooting it — a stale route fails the run instead of quietly saving the 404 page under a real page's name, which is what an earlier, unasserted route list had been doing for four post routes. `check.sh [ref]` builds `exampleSite` from a git worktree at `ref` (default `HEAD`) and from the working tree, then diffs the two file lists; it exits 1 on any path the working tree stopped emitting. Both sides are built on demand, so there is nothing frozen to go stale. It leaves the builds in `.parity/base` and `.parity/cand`, and regenerates them each run — which is the split `.gitignore` draws: **the harness is tracked, only what it rebuilds is ignored.** It was maintainer-local until 2026-08-17, when the copy on this machine turned out to be gone and had to be fetched from another PC: a checker for a binding commitment belongs in the same history as the layouts it checks, and `CONTRIBUTING.md` had been asking contributors to run a script the repo never gave them. An earlier pair of frozen fixture builds was deleted: unrebuildable once the themes that produced them were gone, they had decayed into a permanently-red list of accepted deltas that no new regression could have been spotted in. Do not reintroduce a checked-in baseline.

## Why URL safety matters here

Static hosts are commonly deployed with `rsync --delete`, where any path the build stops generating is deleted from the live host. What the theme can actually take away there is narrower than it first looks, and the narrow part is the one that hurts. Permalinks, `[taxonomies]` and `[outputFormats]` are declared by the consuming site, not here, and a deleted template falls back to another rather than moving a URL. What the theme *does* decide is **which assets the resource pipeline publishes at all**: Hugo emits a resource only where some template evaluates its `RelPermalink`, so a font or icon that only CSS references vanishes from `public/` while `hugo server`, reading from the source directory, keeps serving it. That failure is invisible locally and total in production — see the font loop in `_partials/head-assets.html`, whose `else` branch exists for no other reason. Before changing anything that affects output paths or asset publication, build old and new into separate directories and diff the file lists — that is what `.parity/check.sh` is for.
